# SqueekChain demo design system

## Overview

An educational kinetic benchmark for visitors exploring the fictional Proof-of-Hamster-Work idea. The existing dark, green/gold hamster-wheel identity remains. The wheel and its controls lead; telemetry follows; missions, character concepts, the fictional story and illustrative allocation model are supporting content. Every score is local demo data. Wallets are optional spectators.

Canonical source: `styles.css`, `index.html`, `app.js` and `wallet.js`. `dist/` is an exact static copy generated by `scripts/build.mjs`, not a second source of truth.

## Typography

Local WOFF2 files, defined at `styles.css:1`:

- Space Grotesk variable face, weights 400–700; fallback `system-ui, sans-serif`. Used for headings, prose and controls. The implementation uses 400, 600 and 700.
- IBM Plex Mono regular and semibold files; fallback `ui-monospace, monospace`. Used for numeric metrics and concept identifiers, not paragraph copy.

The six CSS type tokens are `--text-small` .875rem (14px), `--text-body` 1rem (16px), `--text-heading-small` 1.25rem (20px), `--text-heading` 1.5rem (24px), `--text-number` 2rem (32px), and `--text-display` 3rem (48px). At 35rem and below, display becomes 2rem, leaving five distinct rendered sizes. These pixel equivalents assume the browser's default 16px root.

Body line-height is 1.6; UI copy 1.5; h1 1.1; h2 1.3; h3 1.4. Headings use balanced wrapping; paragraphs use pretty wrapping; explanatory text is capped at 68–70ch. Main heading tracking is −.045em desktop and −.035em mobile; h2 −.02em; h3 −.01em. Other content has natural tracking. Dynamic numbers use tabular numerals. Critical values can wrap rather than being ellipsized. The required `TESTNET SIMULATION:` is the intentional uppercase exception.

## Layout

`main` and header/footer containers have a 1208px maximum including 24px inline padding, yielding a shared 1160px content edge. Mobile padding is 16px. The declared spacing steps are 4, 8, 12, 16, 24, 32, 48 and 64px; component declarations also use 20, 40 and 56px where the incumbent density needs them.

The benchmark is one outlined surface with a 1.1:1 two-column grid (`styles.css:90`). Wheel controls and score recording stay together in the first column. Its minimum stage is 290px desktop, 260px intermediate, 176px mobile. Mobile artwork is 160px square, offset to leave readable metric space. Canvas positioning is physical geometry; text alignment, padding and structural separators use logical directions.

Implemented breakpoints:

| Query | Changes |
| --- | --- |
| 68rem / 1088px | Compact panel/card padding to 20px, reduce header gaps, hide the redundant local-mode indicator |
| 54rem / 864px | Stack benchmark and story columns; hide the desktop nav; concept cards become two columns; missions and footer stack |
| 35rem / 560px | 32px main heading; 16px page/panel insets; compact stage and header logo; concept cards and mission rows become one column; dialog becomes a bottom sheet |

Controls wrap when their text needs more room. The header stays in normal flow with the complete disclaimer; neither relies on a fixed-height offset. At 390×844 the product, Spin wheel, turbo, Record Simulation Score and the no-transfer notice are visible without scrolling. Checked widths: 320, 390, 768 and 1440; no horizontal overflow. Text enlargement to 200% and a structural RTL mirror were checked at 390; browser-native zoom and actual translated content were not.

## Elevation & Depth

Flat surfaces use a single 1px structural border and tonal fill. There are no UI box shadows, gradient text, stacked cards or ornamental page glows. The canvas retains its original neon wheel glow as illustration. The dialog is the native browser top layer, with a 75% black backdrop. The skip link is above normal content only while focused.

## Shapes

Benchmark and dialog corners: 16px. Concept-card corners: 12px. Buttons: 8px. Progress tracks: 4px. On mobile the dialog keeps 16px top corners and square bottom corners, with safe-area padding. The 6px status dot is circular and always accompanies a text label. Artwork uses its original circles, ellipses and cyber-hamster geometry.

## Components

| `.telemetry-grid`, `index.html:80`, `app.js:326` | Semantic description-list metrics, updated from local calculations. Native progress bars have labels. The bounded event log is keyboard-scrollable and retains at most 40 rows. |
| `.quest-item`, `index.html:107`, `app.js:311` | Noninteractive progress rows, with text and native progress indicators. Completion is local and grants only demo Aura; no fake global standings or eligibility. |
| `.card-inner`, `index.html:120`, `app.js:435` | Concept art and descriptive traits. IDs are rows beneath headings. Optional mouse tilt is capped at 5 degrees and disabled with reduced motion. |
| `#wallet-dialog`, `index.html:261`, `wallet.js:13` | Native modal, centered on desktop and bottom-aligned on mobile. Shows provider discovery, no-provider, waiting, retry, connected and disconnected states. Closes by close control, Escape or outside click; keyboard Tab wraps within its live controls; focus returns to the connect button. Full addresses are accessible inside the dialog. |
| `<details>`, `index.html:93` | Native keyboard-accessible disclosure for formulas and local-storage scope. No custom accordion code. |

Global focus is a 2px gold outline with a 4px offset (`styles.css:55`), using system Highlight in forced-colors mode. Enter/Space activate native buttons. The skip link reaches `main`. Audio begins muted. Buttons use 120ms named transitions and .96 press scale only with `prefers-reduced-motion: no-preference`. Reduced motion holds canvas art still while keeping calculated scores usable; it also disables card tilt. Turbo has an explicit pause state, and hiding the tab stops progress.

## Do’s and don’ts

- Reuse the existing container edge, type scale and `.sqk-btn` variants when adding an authorized surface. Use section headings and 8px internal / 24px group spacing before adding another border.
- Keep the exact simulator disclaimer and local-only score explanation visible near their respective entry/action points. Display zero until the session actually computes progress.
- Use green fill for the primary wheel action and gold for demo scores/attention. Keep supporting prose in the sans family and data in mono.
- Preserve labels and native keyboard behavior. Keep dynamic notices in stable status regions and full addresses available without truncation.
- Do not introduce token balances, claims, transaction handlers, invented players, official whitelist status or a wallet dependency for scoring. New conceptual numbers must be labeled as illustrative.
- For another educational section, start with `.sqk-section` and `.section-header`, select existing type tokens, and use a semantic list or description list for data. Verify its mobile reading order and reduced-motion behavior before exporting.
